How to read this comparison

Accuracy

The percentage of examples where a prediction exactly matches the known request type. Correct answers ÷ examples × 100.

Known request type

The category assigned in the test data, used here as the reference answer. Filter it to inspect one kind of request.

Disagreement

The methods predicted different categories. Agreement does not prove correctness: all three can agree on a wrong answer.

Read the sample size

Each request type has 40 examples in this dataset. The scores describe this test set, so a small category result should be interpreted with care.

How this was built

The request was a simple dashboard for comparing three saved prediction methods and exploring their mistakes. The default opens on examples with an incorrect prediction. Category filters change the comparison; search and example filters change only the list. The worked counterexample is Beneficiary not allowed, where the overall leader changes.

Built with Browser App Builder’s Plan, Build, CSV-reading, and Campus Designer skills. Papa Parse reads the CSV files; native browser controls and calculations provide the comparison. The local build uses Vite. No training, model calls, accounts, analytics, or saved browser selections are used.

Evaluation on November 4, 2026: all 30 calculation, data, font, and text-rendering checks passed. An independent CSV recount matched the overall and category scores. Browser checks covered filtering, paging, reset, keyboard search, returning visitors, and desktop and narrow layouts. These checks do not verify how the predictions were generated or establish performance on new data.
